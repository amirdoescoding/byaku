# Design + Plan: byaku v0 spike (Away-first feasibility)

Generated by /office-hours + /plan-eng-review on 2026-11-25 · Repo: amirdoescoding/byaku · Mode: Builder · Status: APPROVED

## Context
- No code exists yet. Before any product or UI code, the spike answers four yes/no questions on the dev M1 (macOS 15.6, Command Line Tools only):
  - (a) Does SwiftPM build and test with Command Line Tools only?
  - (b) What is the real power cost of camera + Vision?
  - (c) Does a lock method verifiably lock on macOS 15?
  - (d) Can an embedding model tell the owner from strangers?
- The headline feature is the café demo. You arm Away, walk off, a stranger looks, and byaku sounds the alarm and locks the Mac.
- Audience: students, office workers, and agent users who keep laptops open.

## Product decisions (office hours)
- **Away v1:**
  - The threat is eyes on an unlocked screen, and arming is manual.
  - Any non-owner face looking while armed triggers sound + lock.
  - The owner's face only suppresses triggers; disarming takes an explicit click (Touch ID later). This closes the photo-of-owner spoof.
- **Owner-aware is core.** It covers an onboarding face scan plus a whitelist of trusted faces added by scan or photo.
- **Targets:** Apple silicon, macOS 14+.
- **Distribution:** a signed `.app` on GitHub Releases. Not the App Store, because the lock uses a private API.
- **Deferred:** auto-arm, the "who looked" log, frosted glass, per-window blur, context-aware strictness. All are listed in TODOS.
- **UI:** after the spike, mock up with canvas-design / emil-design-eng, then critique with impeccable, then build.

## Environment facts (verified)
- Swift 6.1.2 with `Testing.framework` in Command Line Tools. There's no XCTest and no `coremlcompiler`, so models compile at runtime with `MLModel.compileModel(at:)`.
- An iPhone Continuity Camera is attached, so the code must pin the built-in camera.
- `powermetrics` supports the `cpu_power`, `gpu_power` and `ane_power` samplers.
- `ioreg AppleSmartBattery` exposes Voltage and InstantAmperage. InstantAmperage reads 0 while plugged in.
- `login.framework` lives in the dyld shared cache. `SACLockScreenImmediate` stays unverified until the spike runs it.

## PR1: `feat/v0-spike` (steps 1–4)
**Files:** `Package.swift`, `Sources/Byaku/Camera.swift`, `Sources/Byaku/main.swift`, `Tests/ByakuTests/ByakuTests.swift`, `scripts/power.sh`, plus docs.

1. **Skeleton.** Tools 6.0, `.macOS(.v14)`, `swiftLanguageModes: [.v5]`, one executable target `Byaku` and `ByakuTests` using swift-testing. Parse arguments from `CommandLine.arguments`, with no dependencies.
   → verify: `swift build && swift test` pass. If `swift test` fails under Command Line Tools, stop and record it.
2. **`byaku detect --fps N`** (`Camera.swift`).
   - Pin the camera with `AVCaptureDevice.DiscoverySession(.builtInWideAngleCamera)`.
   - Choose an explicit low-resolution `activeFormat`, start the session, then set `activeVideoMin/MaxFrameDuration` under `lockForConfiguration` (D13).
   - Set `alwaysDiscardsLateVideoFrames = true` and reuse a single `VNSequenceRequestHandler`.
   - Run `VNDetectFaceRectanglesRequest` revision 3 and print `faces=N [yaw,pitch]`.
   - Every 10 s, print the **delivered fps**. If 1 fps isn't supported, the frame-drop fallback prints "sensor at full rate".
   - Exit loudly with a clear exit code when camera access is denied or no built-in camera exists.
   - Frames are never written to disk. Record which terminal app the command ran from, since camera permission belongs to that app.
   → verify (user, real camera):
     - `faces=1` with only you in frame.
     - `faces=2` with a second person or a photo.
     - Yaw follows your head turns.
     - Delivered fps is roughly the requested fps.
3. **Power** (`scripts/power.sh`, D10, D14).
   - Battery runs: unplugged, fixed brightness, powermetrics not running. Alternate idle / 1 / 2 / 5 fps, 3 runs of ~120 s each per setting. Read `ioreg` Voltage × InstantAmperage and report mean ± sd of the delta against idle.
   - Separate `sudo powermetrics --samplers cpu_power,gpu_power,ane_power` runs for the rail breakdown.
   - A row only counts if its delivered fps matches the label.
   → output: a power table in ARCHITECTURE. Update AGENTS.md invariant 3 to name both measurements.
4. **`byaku lock-test`** (run by you, since it locks the screen).
   - First, read BLEUnlock's lock code and issues.
   - Primary: `dlopen` `login.framework`, then `SACLockScreenImmediate`. Fallback: `pmset displaysleepnow`, which only counts if a password is required immediately.
   - Verify: 3 s later, `CGSessionCopyCurrentDictionary()["CGSSessionScreenIsLocked"] == true`, and unlocking asks for a password.
   - Also log whether camera frames keep arriving while locked.
   - Exit loudly if the lock symbol is missing.
5. **Close-out.**
   - Update AGENTS.md Commands, the ARCHITECTURE decision log (lock method, power table, "suppress, not disarm"), MEMORY, RESTART and TODOS (see TODO list below).
   - Write the `.logs/2026-11/25/v0-spike.md` recap; recaps are committed.
   - Run `graphify update .` and `git check-ignore .env`.
   - Log the gstack review (`gstack-review-log`, deferred from plan mode).
   - Open the PR (CI and CodeQL activate).

## PR2: `feat/v0-owner-match` (step 5, NEXT SESSION, after PR1 merged; D16)
6. **`ml/` (uv).**
   - `pyproject.toml` with opencv-python, onnxruntime, onnx2torch, torch, coremltools. Models are git-ignored.
   - `ml/sface_live.py` (D17): OpenCV `FaceDetectorYN` + `FaceRecognizerSF.alignCrop`, live from the camera, frames in memory only. Enroll the owner for ~5 s, then score every face live in the same run (D11).
   - Pre-registered pass bar (D15): min(owner) > max(stranger), measured across yaw 0/±30°, 2 lighting setups and glasses on/off, with ≥2 strangers or their photos. Also score a photo of the owner. Record the margin and a provisional threshold.
   - `ml/convert_sface.py` (D12): ONNX → onnx2torch → trace → coremltools `.mlpackage`, with BGR/RGB order and raw 0–255 input pinned.
   - Parity: assert cosine > 0.99 against onnxruntime on ≥5 aligned **public sample** faces, never camera captures.
   - If onnx2torch fails, record "conversion blocked" and stop.
7. **`byaku embed`** (Swift, D18).
   - Compile the `.mlpackage` at runtime with `computeUnits = .all`.
   - Embed the parity faces and check them against Python's numbers.
   - Report placement via `MLComputePlan` and the latency of `.all` vs `.cpuOnly`.
   - Run `scripts/power.sh` with embedding at 1 Hz.
   - Treat the Vision feature print as a cheap baseline only; it is expected to lose.
8. **Close-out.** Same as step 5: record the matcher decision and its power cost in ARCHITECTURE.

## Tests (D9 as amended by D17)
`Tests/ByakuTests/ByakuTests.swift` holds table-driven swift-testing tests:
- `parseFPS` clamps to the valid range and rejects bad input.
- `cosine`: identical vectors give 1, orthogonal give 0, a zero vector gives no NaN.
- The similarity-transform test is dropped along with the Swift alignment.

Python parity is enforced by an assert in `convert_sface.py`. The camera, lock and real-face checks are manual and required (AGENTS.md).
```
CODE PATHS                              USER FLOWS (manual, real camera)
main.swift parseFPS   [planned ★★★]     detect: 1 face / 2 faces / yaw / delivered fps
main.swift cosine     [planned ★★★]     lock-test: locked=true + password prompt
Camera.swift          [→MANUAL]         sface_live: pass bar D15
convert_sface.py      [parity assert]   embed: ANE placement + power
```

## Failure modes
| Path | Realistic failure | Handling |
|---|---|---|
| detect | Camera permission denied for the terminal app / Continuity Camera selected | Exit with a clear error; pin built-in camera |
| detect/power | fps silently reset to 30 | Delivered-fps print; mismatched rows rejected |
| lock-test | Private symbol missing on 15.x | Loud exit → pmset fallback, documented |
| convert | onnx2torch op mistranslation / BGR swap | Parity assert fails loudly; "conversion blocked" |
| embed | CoreML falls back to CPU | MLComputePlan + latency compare, power run |

There are no critical gaps: every failure is either loud or explicitly checked.
