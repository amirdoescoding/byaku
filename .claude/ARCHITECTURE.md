# Architecture

Status: **menu-bar app with Guard actions** (`byaku app`: Guard, face setup, delete, Mode ladder, banner, Iris mist/dim; UI.swift/App.swift/Alert.swift/Tokens.swift/Owner.swift). Before that, a **v0 spike CLI** (`Sources/Byaku`: `detect [--embed]`, `embed`, `lock-test`; `ml/`: SFace conversion + live eval). The app pipeline below is still planned.

## Pipeline

```
AVCaptureSession (low res ~640×480, adaptive 1–5 fps)
        │  CVPixelBuffer, in memory only
        ▼
Detect: Vision VNDetectFaceRectanglesRequest (ANE)
        │  faces[] with bbox, yaw, pitch, roll
        ▼
Owner: is this face the enrolled owner?
        │  Vision landmarks → 5 points → similarity warp to the 112×112 ArcFace template (CPU, bilinear)
        │  SFace embedding (CoreML) vs stored embedding, cosine threshold
        │  cheap path first: largest, most central face = owner candidate
        ▼
Gaze: is this non-owner face looking at the screen?
        │  v0: yaw/pitch thresholds from VNFaceObservation
        │  v1: small trained CoreML classifier on face crops (see ml/)
        ▼
Policy: debounce (N of last M frames), cooldown, mode
        ▼
Actions
  Guard: banner, dim overlay
  Away:  loud sound + lock
```

## Modes

| Mode | Who counts as a threat | Actions | Failure behavior |
|------|------------------------|---------|------------------|
| Guard | Any non-owner face looking at the screen | Banner and/or dim (configurable) | Fail open: stop guarding and show an icon state |
| Away | Any facing face but the owner's, a lone unembeddable face included | Lock + siren/voice until unlock | **Fail closed: lock** (start error, or no frame for 10 s) |

## Actions

- **Banner** (shipped): `BannerPanel`, a non-activating 320×64 panel under the status item at `.statusBar + 1`, never key.
- **Iris / dim** (shipped): `WatchOverlay`, one click-through borderless window per screen at `.statusBar`, below the menu
  bar; gradient-strip mist and/or 40% black. Chosen per alert by the Mode ladder (Whisper/Iris/Shade/Awaken).
- **Guard sound** (shipped, opt-in): one `NSSound("Submarine")` per alert.
- **Away alarm** (shipped, `Alarm.swift`): an `AVAudioEngine` built per alarm, looping either `siren(t)` (960/770 Hz two-tone,
  `AVAudioSourceNode`) or a picked `/System/Library/Sounds` file (`AVAudioPlayerNode`) at `toneGain` (siren × `sirenTrim`), with the
  message on top from the first moment: the user's `message.m4a` (`AVAudioPlayer`) or `AVSpeechSynthesizer`, repeated 1 s after it
  ends, until unlock. Default output unmuted at the alarm volume (CoreAudio `VirtualMainVolume`/`Mute`), restored on stop.
  `MessageRecorder` (`AVAudioRecorder`) records the message from `MessagePanel`; the mic runs only while recording.
- **Lock** (shipped): `lockScreen()` = `SACLockScreenImmediate` (private, dlopen). `lock-test` falls back to `pmset displaysleepnow`.
- **Onboarding** (shipped, `Onboarding.swift`): `OnboardingFlow` (one borderless floating window, step state machine with a
  `run` token), `MascotView` (brand mark as CALayers; blades = translate › rotate-about-base › scale layers driven by
  `springTo`), `CoachOverlay` (full-screen click-through panel at `.popUpMenu + 1` over the real menu; AppController forwards
  `menuWillOpen` / `willHighlight` / `menuDidClose`), `Sfx` (synthesised WAV NSSounds), `WordmarkView` (tiny SVG path reader).
  Enrollment phases route through `showEnroll` to the window or the Set up face panel. `founder.mp4` is bundled by `bundle.sh`.
- **Face scan** (shipped PR B1, `ScanView.swift`, spec `docs/designs/face-scan.md`): one `ScanView` hosted by the onboarding
  window and `EnrollPanel`. `Camera.onLandmarks` (largest face, 15 fps) → `ScanFrame` → One-Euro → `ScanGeometry.fit` (canonical
  mesh posed by yaw/pitch/roll, LSQ scale+offset, vertices pulled onto Vision points) → CAShapeLayers. `ScanPose` (Owner.swift) =
  pure straight/left/right hold machine. Mesh = `ScanMesh.swift`, generated by `ml/scan_mesh.py` from MediaPipe's canonical face.
  Camera image = our own frames (`Camera.onImage` → CI mono/mirror → layer contents) until the sweep; no preview layer (deadlock). Template = straight-hold prints only (unchanged math).

## Power tactics

Most of the savings come from the pipeline, not the language.

- Use the lowest camera preset that still detects faces at ~2 m, and set the frame rate on the device rather than dropping frames.
- Adaptive rate: ~1 fps when only the owner is visible, bursting to ~5 fps when a new face appears.
- Skip owner matching and gaze checks when only one face is present and it matches the last owner track.
- Keep everything on the ANE (Vision, CoreML). No CPU inference loops.
- Measure each change with `powermetrics`, and log the numbers here.

## Power measurements

`scripts/power.sh`: whole-system draw from the battery (`ioreg` Voltage × InstantAmperage). Conditions: unplugged, fixed brightness, 3 × 120 s alternating runs, powermetrics not running. M1, macOS 15.6.1, 2026-11-25, `byaku detect` release build. The sensor stays at 30 fps in every row.

| Setting | Processed fps | Mean ± sd (W) | Δ vs idle, all runs | Δ vs idle, runs 2–3 |
|---------|---------------|---------------|---------------------|---------------------|
| idle | – | 7.386 ± 0.547 | 0 | 0 (idle 7.00) |
| detect 1 fps | 1.0 | 7.146 ± 0.193 | −0.24 | +0.28 |
| detect 2 fps | 1.9 | 7.397 ± 0.018 | +0.01 | +0.39 |
| detect 5 fps | 4.5 | 7.727 ± 0.413 | +0.34 | +0.95 |

The idle sample in run 1 (8.16 W) looks like warm-up from the release build that had just compiled. It inflates the idle sd, so the run 2–3 column is the more honest read.

Takeaway: camera + Vision costs roughly 0.3–0.4 W at 1–2 fps and roughly 1 W at 5 fps. Noise is about ±0.5 W. All settings fit the 1.5 W budget, so keep a ~1–2 fps baseline and burst to 5 fps only briefly.

## Swift alignment (`byaku align`, `byaku match`)

- **Warp parity** (YuNet points → Swift solve + warp → SFace vs `alignCrop`): worst cos **1.00000** over 8 faces (bar 0.99). It reads a
  lossless `parity/sample.png`, because ImageIO and libjpeg decode `sample.jpg` ~3.5 levels apart (mean abs).
- **Landmark parity** (Vision points instead of YuNet): 7/8 faces matched, worst cos 0.06, FAIL vs 0.98 (reported, not gating). The two large
  faces reach 0.97/0.92; the small faces fail badly. `sample.jpg` is an annotated demo image (boxes and dots painted on the faces), so this is
  a weak proxy. Vision also finds only 2 faces in the full 2048 px image, so the check runs Vision on a 2× crop per face.
- **Live gate** (`byaku match` + `ml/score_segments.py`, counting rule pre-registered in af2f29e, confidence cut amended 0.9 → 0.5 in 579821d
  before any scored data, because Vision scores a clear face 0.82–0.85):

| Segment | n | p5 | p50 |
|---|---|---|---|
| owner, light A, yaw 0 / +30 / −30 | 46 / 45 / 45 | 0.952 / 0.736 / 0.578 | 0.962 / 0.763 / 0.623 |
| owner, light B, yaw 0 / +30 / −30 | 45 / 45 / 45 | 0.788 / 0.593 / 0.381 | 0.811 / 0.676 / 0.458 |
| owner, glasses on / off | 46 / 46 | 0.791 / 0.847 | 0.802 / 0.856 |
| stranger 1 / 2 (photos) | 38 / 45 | p95 0.113 / 0.159 | 0.088 / 0.098 |
| owner photo (report only) | 41 | 0.538 | 0.623 |

Result: v2 **PASS**, margin +0.228, threshold 0.300, FRR 0.3% / FAR 0%. Bar v1 (record only) FAILs at −0.155 because of one 0.042 frame in
owner A −30. Frontal faces match as well as in Python (0.95). Turned heads lose a lot (Python held 0.94 / 0.79 at −30), so the weak point is
Vision landmarks on yawed faces, not the warp.

## Embed cost (powermetrics rails, `detect --fps 1` vs `--embed`, face in view, 60 × 1 s, medians)

| Rail | detect | + embed (CPU+ANE) | + embed (`.all`, before fix) | + landmarks + align + embed (PR3) |
|---|---|---|---|---|
| GPU | ~16 mW | ~16 mW | 100–165 mW while a face is visible | 8 mW |
| ANE | ~15 mW | ~17 mW | ~17 mW | 17 mW |
| CPU | ~70 mW | ~90 mW (noisy) | – | 100 mW |

PR3 alignment (Vision landmarks on the rev-3 rect + 112×112 CPU warp, 32BGRA camera output) adds ≲ +10 mW CPU at 1 Hz, nothing on the GPU.

Placement (`MLComputePlan`, CPU+ANE): 58 ops on the ANE and 4 on the CPU (the linear head). Latency: 1.25 ms (CPU+ANE),
1.5 ms (`.all`), 3.1 ms (CPU only). Embedding at 1 Hz costs ~+20–25 mW, which is below battery-measurement noise.

## Open risks
- **Camera permission (TCC)**: solved by `Byaku.app` (own prompt). Ad-hoc signing ties the grant to the cdhash, so a rebuild may
  re-prompt (`tccutil reset Camera dev.byaku.app`). A stable signing identity, then Developer ID + notarization, is still open.
- **Gaze accuracy.** Yaw/pitch thresholds alone will false-positive on people looking near the screen. Vision rev-3 yaw/pitch granularity is not verified live yet (continuous vs binned). EyesOff
  trained a custom ~300k-parameter classifier on ~80k images.
