# Memory: key facts & decisions

- 2026-11-25: byaku = macOS menu-bar shoulder-surfer detector. Guard mode (banner/dim) + Away mode (sound + lock).
- **Power is the #1 priority.** Hence Swift + Vision/CoreML (ANE), not Python + OpenCV (CPU).
- Python only lives in `ml/` (uv) for model eval, conversion and training. It is never shipped.
- macOS first. MIT license.
- Impeccable stays for UI. `DESIGN.md` and `PRODUCT.md` live at the repo root because impeccable reads them there.
- Only Xcode Command Line Tools are installed (no Xcode). swift-testing works and XCTest is absent. There's no `coremlcompiler`, so models compile at runtime.
- Prior art: EyesOff (YuNet + ~300k-param gaze classifier, ~1.5 W on M2 Air). CompreFace was rejected as too heavy.
- 2026-11-25 spike: the lock is `SACLockScreenImmediate` (verified on 15.6). The camera keeps running while locked. The M1 FaceTime camera is fixed at 30 fps, so low fps is a software throttle. Detect costs ~0.3–0.4 W at 1–2 fps.
- Away v1: manual arm. The owner's face suppresses triggers but never disarms (photo spoof). Disarm is a click.
- 2026-11-25 PR2: SFace passes owner-vs-stranger (bar v2, margin +0.633, threshold 0.437). It converts to CoreML (onnx2torch route) with exact parity. Run it with `.cpuAndNeuralEngine`, because `.all` wakes the GPU (+0.1 W). Embed cost is ~20–25 mW at 1 Hz.
- Pre-register pass bars in a commit before collecting data. Live labelling is error-prone: the owner holding a phone photo gets scored as the "stranger".
- 2026-11-25 PR3: Swift alignment matches `alignCrop` exactly (own bilinear warp; vImage = Lanczos + bottom-left origin). Swift live bar v2 PASS but margin +0.228 (threshold 0.300): turned heads (yaw −30) are the weak point, from Vision landmarks. Vision face confidence is ~0.83 for a clear face, which is not YuNet's scale. Power: ≲ +10 mW CPU.
- Test images: ImageIO and libjpeg decode JPEGs differently. Swift parity checks read a lossless PNG written by Python.
- Workflow: one PR per session. Stop after each PR for the user's OK, and the context gets cleared between PRs.
- 2026-11-25 PR4 brand ("Pale Watch", quiet shinobi): symbol E2 is a thin ring with two blade crescents that sit *above* centre on purpose (the user rejected a centred version). Wordmark is Rondel 500, lowercase `byaku`; 白眼 appears only in an optional lockup. Accent is pale iris #C8BFEF on ink and dusk violet #6A5DB8 on paper (pale iris is 1.6:1 on white). Everything is generated by `design/brand/src/final.py`. Edit the geometry and colours there.
- 2026-11-25 PR5 menu-bar app: `byaku app [model]` (launch from Terminal; there's no .app yet). Icons: full mark in every state; off = ink, guarding = violet,
  alert = violet + dot, error = ink + slash (off vs guarding is colour-only, accepted by the user). The panel grows from the status item.
  Colours/timings live only in Tokens.swift (CI: scripts/check-ui.sh). UI work: canvas mockups → user OK → code → ui-designer + frontend-developer review.
- AppKit gotchas: NSMenu `autoenablesItems` must be false or `isEnabled` is ignored. Manual CAShapeLayer sublayers animate
  implicitly (wrap in CATransaction.setDisableActions). Camera.start can finish after a cancel, so stop any camera with no owner.
- 2026-11-26 PR6 Guard actions: Mode ladder Whisper/Iris/Shade/Awaken (default Iris + banner), banner rotates one line per alert,
  "Lift for now" ⌘L. The user chose a soft violet mist over a crisp rim (and over the brand's no-glow rule): it ships as gradient
  strips because a full-screen blurred shadow costs GPU on every recomposite. Measure overlay power with labelled phases
  (idle / held / scrolling) and no video playing; the user's 1–2 W reading was a browser video.
- No Screen Recording permission for VS Code: `screencapture` returns wallpaper only. Verify windows via CGWindowListCopyWindowInfo instead;
  NSStatusItem frames are only real under `NSApp.run` (RunLoop.main.run in a test gives (0,-24)).
- Guard sound: Epidemic Sound files can't be bundled in this MIT repo; use macOS system sounds or self-made audio.
- 2026-11-26 PR7 app bundle: `scripts/bundle.sh` → `build/Byaku.app`; launch with `open build/Byaku.app` (running the inner binary gives TCC
  to the terminal). Bundle id `dev.byaku.app` (never change). Settings (UserDefaults) moved to that domain, so they reset once; the owner
  embedding in Application Support carries over. App icon: render the SVG with AppKit (`NSImage(contentsOfFile:)`), not `qlmanage`, which paints a white background.
- 2026-11-26 PR9 Away mode: siren computed in code + system voice (no file, no licence); unlock = disarm; fail closed locks
  without the siren. Away icon = solid iris. `byaku alarm-test [s]` plays it (LOUD, restores volume). Always `git fetch` and branch
  from origin/main: local main was stale again this session (PR #9 had landed).
- 2026-11-26 PR8 Open at login: SMAppService.mainApp works with ad-hoc signing and survives rebuilds at the same path. Guard state is
  persisted (`guard` key) and resumed at launch: the user chose this (camera comes on at login only if Guard was left on).
  `bundle.sh --install` quits the old copy by bundle id (osascript), never `pkill -x byaku` (would kill CLI runs). Build needs Apple silicon (torch 2.7.0 arm64 wheel only).
- 2026-11-26 PR10 release: no Apple Developer account, so releases are ad-hoc + unnotarized (README: Privacy & Security → Open Anyway;
  Sequoia dropped right-click → Open). Local builds sign with self-signed "byaku dev" (`scripts/dev-identity.sh`, LibreSSL
  `/usr/bin/openssl`; Homebrew OpenSSL 3 p12s fail `security import`) so the DR is the cert leaf and rebuilds keep TCC.
  Models are sha256-pinned in `ml/fetch.py`. CoreML parity passes on GitHub's macos-15 runner (0.99994). Onboarding redesign waits until after MVP + devops.
- 2026-11-26 PR11 Away sounds: the tone and message play together. The user tuned the levels by ear: toneGain 0.45, and an extra sirenTrim 0.25 on the siren
  only, because the clipped square was far louder than the system sounds at the same gain. A sound-picker row is a custom NSMenuItem view
  (`SoundRow`): a plain item always closes the menu, and the user wanted iPhone-style pick-and-hear. The user dropped "Play test". The message
  is `Application Support/byaku/message.m4a`, and the mic runs only while recording.
- 2026-11-26 PR12 onboarding: welcome → face → tour on the REAL menu (coach bubble in a click-through panel at `.popUpMenu + 1`,
  driven by NSMenuDelegate `willHighlight` + the pointer's y) → founder video with a lockup intro/outro. The mark is the mascot
  (blades = eyebrows). Sounds synthesised (Epidemic can't ship in MIT). Launch/marketing videos use Remotion + three.js; the
  app stays native Core Animation.
- AppKit gotchas from PR12: an accessory app's `NSApp.activate()` doesn't beat the front app (macOS 14) → onboarding window is
  `.floating`. While an NSMenu is open, `DispatchQueue.main.asyncAfter` blocks didn't run but `.common` Timers did → animations
  that must run during the tour are single keyframes or common-mode Timers. A hidden, re-added layer-backed view can lose a layer
  transform → place resting views by frame, use transforms only for motion. Build full-screen overlays ahead (first composite stutters).
- Synthetic mouse events (CGEvent post) trigger the Accessibility prompt; the user denied it. Verify UI by screenshot
  (`screencapture` works now) + the user walking through it.
- 2026-11-27 PR B1 face scan: mesh mask (MediaPipe canonical, decimated to 160 v), the camera shows only until the sweep
  (the user's sequence: camera alone 1 s → mask fades on top → sweep wipes the camera). The prototype uses the same 2D projection
  math as Swift (no three.js) so tuning transfers. The Vision→mesh map is measured, not hand-written. Vision yaw/roll signs
  = ours (+yaw = the user's own left); pitch sign unmeasured. B1 template = straight-hold prints only; B2 decides yawed prints.
  `cacheDisplay` snapshots drop CAShapeLayer alpha/opacity: don't judge colours from them.
